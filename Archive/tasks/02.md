# HistorySim Lite 课程任务卡

## 第 2 次课：标准剧本数据、SQLite 表结构与校验

### 一、本次主题

本次课建立标准剧本数据规范，明确静态剧本数据与运行存档的区别，并设计 SQLite 表结构草案。

### 二、课程目标

1. 说明剧本数据、运行状态和存档数据的区别。
2. 设计标准数据结构。
3. 理解 ID 唯一性、外键引用和数值范围校验。
4. 建立 SQLite schema 草案。

### 三、任务：课堂完成

1. 建立 scenarioTypes.ts。
2. 编写 5 个地区、2 个势力、5 个人物样例数据。
3. 实现 validateScenarioShape()。
4. 撰写 docs/DATABASE_SCHEMA.md 初稿。

### 四、任务：课后延拓

1. 补齐 30 个地区、4 个势力、50 个人物、20 个技能、10 个事件。
2. 至少写 10 条数据校验规则。
3. 形成 docs/SCENARIO_DATA_DICTIONARY.md。

### 五、知识点

剧本数据是初始世界配置，运行状态是回合推进后的 GameState。SQLite 既可保存剧本，也可保存完整 GameState JSON。教学阶段优先保证数据一致性：ID 唯一、引用有效、地图连通、数值不为负、地区连接双向一致。

### 六、示例框架代码（TS 版）

```ts
export interface ScenarioData {
  id: string;
  name: string;
  regions: Region[];
  factions: Faction[];
  persons: Person[];
  skills: SkillDefinition[];
  events: EventDefinition[];
}

export interface ValidationIssue {
  level: "error" | "warning";
  message: string;
}

export function validateScenarioShape(data: ScenarioData): ValidationIssue[] {
  const issues: ValidationIssue[] = [];
  if (data.regions.length !== 30) issues.push({ level: "warning", message: "Region count should be 30." });
  if (data.factions.length !== 4) issues.push({ level: "warning", message: "Faction count should be 4." });
  const regionIds = new Set(data.regions.map(r => r.id));
  if (regionIds.size !== data.regions.length) issues.push({ level: "error", message: "Duplicate Region ID." });
  const factionIds = new Set(data.factions.map(f => f.id));
  for (const r of data.regions) {
    if (!factionIds.has(r.ownerFactionId)) issues.push({ level: "error", message: `${r.id} has invalid owner.` });
  }
  return issues;
}
```
