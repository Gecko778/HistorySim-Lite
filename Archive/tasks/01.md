# HistorySim Lite 课程任务卡

## 第 1 次课：项目启动、领域建模与 Tauri 工程骨架

### 一、本次主题

本次课从历史策略模拟问题出发，建立 HistorySim Lite 的领域模型和工程骨架。重点是明确系统是以模拟内核为中心的可测试系统。

### 二、课程目标

1. 说明 HistorySim Lite 的系统目标、统一规模和基础命令。
2. 区分技术栈的各组成部分。
3. 建立项目目录和核心领域类型。
4. 理解模拟内核不依赖 UI 的架构原则。

### 三、任务：课堂完成

1. 创建 Tauri + React + TypeScript 项目。
2. 建立 src/core、src/ui、src/rendering、src/data、src/persistence、src/app 目录。
3. 编写 Region、Faction、Person、Army 基础类型。
4. 首页显示项目名称和标准数据规模。

### 四、任务：课后延拓

1. 撰写 docs/PROJECT_CHARTER.md。
2. 绘制领域模型图。
3. 说明 5 类基础命令的业务含义。
4. 提交第一次 Git commit。

### 五、知识点

领域建模将历史世界转换为软件对象。本项目的核心对象包括 Region、Faction、Person、Army、Skill、Event、Command 和 GameState。Tauri 提供桌面应用壳层，React 管理界面，PixiJS 渲染地图，SQLite 保存本地数据，TypeScript Core 负责状态演算，注意它不应该导入 React、PixiJS、Tauri API。

### 六、示例框架代码（TS 版）

```ts
export type RegionId = string;
export type FactionId = string;
export type PersonId = string;
export type Terrain = "plain" | "mountain" | "river" | "coast" | "forest";

export interface Region {
  id: RegionId;
  name: string;
  ownerFactionId: FactionId;
  terrain: Terrain;
  x: number;
  y: number;
  population: number;
  agriculture: number;
  commerce: number;
  publicOrder: number;
  defence: number;
  food: number;
  troops: number;
  neighbours: RegionId[];
}

export interface Faction {
  id: FactionId;
  name: string;
  rulerPersonId: PersonId;
  colour: string;
  capitalRegionId: RegionId;
  gold: number;
  food: number;
  prestige: number;
  aiControlled: boolean;
}

export interface Person {
  id: PersonId;
  name: string;
  factionId: FactionId;
  locationRegionId: RegionId;
  age: number;
  status: "active" | "captured" | "dead" | "retired";
  command: number;
  strength: number;
  intelligence: number;
  politics: number;
  charisma: number;
  loyalty: number;
  ambition: number;
  skillIds: string[];
}
```

### 八、验收标准

- 术语、数量和基础命令与统一项目范围一致。
- TypeScript Core 中的代码不依赖 React、PixiJS 或 Tauri UI。
- 课堂任务能够在本地运行或通过测试验证。
- 课后延拓有文档、提交记录和必要截图或日志。
