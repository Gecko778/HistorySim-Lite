# 学生项目实施手册

## 一、项目名称

HistorySim Lite：历史策略模拟系统

## 二、项目目标

本项目要求学生以小组为单位，开发一个简化的历史策略模拟系统。系统应能够加载 30 个地区、4 个势力、50 个历史人物、20 个技能和 10 个事件的数据，支持玩家执行开发、征兵、移动、攻击和任命 5 类命令，并通过回合推进实现势力发展、AI 行动、战斗结算和事件触发。

项目不要求复杂美术和商业化游戏效果。评价重点为算法应用、架构设计、数据组织、测试质量和文档完整性。

## 四、小组分工

每组 4 至 5 人。建议分工如下：

| 角色 | 职责 |
|---|---|
| 项目负责人 | 维护任务列表、组织合并、负责答辩流程 |
| 算法负责人 | 负责路径搜索、战斗、AI 和复杂度说明 |
| 架构负责人 | 负责模块划分、接口设计、重构和架构文档 |
| 数据负责人 | 负责地区、势力、人物、技能、事件数据 |
| UI 与测试负责人 | 负责地图界面、命令输入、日志显示和测试报告 |

小组成员可以兼任，但最终提交时必须说明每位成员的具体贡献。

## 五、推荐实现顺序

项目应按“内核优先、界面随后”的顺序完成：

1. 建立数据模型；
2. 加载标准数据；
3. 实现地图图模型；
4. 实现路径搜索；
5. 实现 GameState 与命令系统；
6. 实现开发、征兵、任命；
7. 实现移动和攻击；
8. 实现战斗结算；
9. 实现 AI 行动；
10. 实现事件系统；
11. 重构模块结构；
12. 实现地图 UI；
13. 实现日志与存档；
14. 完成测试和文档；
15. 准备答辩。

## 六、技术要求

课程不强制规定唯一技术栈，但系统必须满足以下工程要求：

1. 模拟内核可脱离 UI 运行；
2. 地图、战斗、AI、事件、存档为独立模块；
3. 使用 Git 管理项目；
4. 提供清晰的运行说明；
5. 提供核心算法测试；
6. 保存随机种子以支持复现；
7. 日志能够解释主要状态变化。

推荐技术路线为：TypeScript + React + Canvas/SVG/PixiJS + JSON/SQLite。也可使用 Python + FastAPI + Web 前端，或其他教师认可的技术方案。

## 七、数据设计要求

最终项目应包含：

1. 30 个地区，组成连通图；
2. 至少 40 条地区连接关系；
3. 4 个势力，每个势力至少初始控制 3 个地区；
4. 50 个历史人物，每个势力至少初始拥有 8 人；
5. 20 个技能，覆盖内政、战斗、AI 和人物四类效果；
6. 10 个事件，包含 4 个随机事件、4 个历史事件和 2 个系统事件。

数据应保持 ID 唯一、引用有效、数值范围合理。

## 八、算法说明要求

项目必须在 ALGORITHMS.md 中说明以下内容：

1. 地图如何建模为图；
2. BFS 或 Dijkstra 如何用于移动和可达性；
3. 资源增长公式如何设计；
4. 战斗战力公式如何设计；
5. AI 如何生成候选行动和选择行动；
6. 随机数如何控制和复现；
7. 主要算法的时间复杂度；
8. 主要边界条件如何处理。

## 九、架构说明要求

项目必须在 ARCHITECTURE.md 中说明以下内容：

1. 系统分层结构；
2. 模块职责；
3. 模块依赖关系；
4. GameState 的作用；
5. 命令执行流程；
6. 回合推进流程；
7. 日志和存档设计；
8. 系统可扩展点。

## 十、提交规范

最终提交应包含：

1. 项目源代码；
2. 标准剧本数据；
3. README；
4. SRS.md；
5. ARCHITECTURE.md；
6. ALGORITHMS.md；
7. TEST_REPORT.md；
8. USER_MANUAL.md；
9. 答辩材料；
10. 小组贡献说明。

提交文件应放在统一仓库中。文档名称、模块名称和术语应保持一致。
