# 术语表

## 一、统一项目术语

| 中文术语 | 英文术语 | 说明 |
|---|---|---|
| 历史策略模拟系统 | Historical Strategy Simulation System | 本项目的系统类型 |
| 地区 | Region | 地图上的基本区域节点 |
| 势力 | Faction | 控制地区和人物的集团 |
| 人物 | Person | 具有属性、忠诚和技能的角色 |
| 军队 | Army | 可移动并参与战斗的兵力单位 |
| 技能 | Skill | 对内政、战斗或 AI 产生影响的能力 |
| 事件 | Event | 满足条件后触发的状态变化 |
| 命令 | Command | 玩家或 AI 提交的行动 |
| 世界状态 | GameState | 某一回合的完整系统状态 |
| 回合 | Turn | 系统状态推进的基本时间单位 |
| 回合日志 | Turn Log | 记录回合内状态变化的文本或结构化数据 |
| 剧本 | Scenario | 初始地图、人物、势力和事件配置 |
| 存档 | Save | 保存的 GameState 和相关日志 |
| 随机种子 | Random Seed | 控制随机过程复现的初始值 |
| 效用评分 | Utility Score | AI 评估行动价值的分数 |
| 可达性 | Reachability | 从一个地区能否到达另一个地区 |
| 最短路径 | Shortest Path | 连接两个地区的最短或最低成本路径 |

## 二、基础命令术语

| 中文命令 | 英文标识 | 说明 |
|---|---|---|
| 开发 | DEVELOP | 提升地区农业、商业、治安或城防 |
| 征兵 | RECRUIT | 消耗人口和资源增加兵力 |
| 移动 | MOVE_ARMY | 将军队从一个地区移动至另一个地区 |
| 攻击 | ATTACK | 对敌方地区发起战斗 |
| 任命 | APPOINT | 任命人物为太守或将领 |

## 三、人物属性术语

| 中文属性 | 英文属性 | 说明 |
|---|---|---|
| 统率 | Command | 影响军队指挥和战斗组织 |
| 武力 | Strength | 影响个人战斗或局部战斗修正 |
| 智力 | Intelligence | 影响计策、事件或 AI 修正 |
| 政治 | Politics | 影响内政开发和地区治理 |
| 魅力 | Charisma | 影响忠诚、招募和势力凝聚 |
| 忠诚 | Loyalty | 表示人物对势力的忠诚程度 |
| 野心 | Ambition | 表示人物叛离或独立倾向 |

## 五、事件分类术语

| 英文术语 | 中文术语 | 说明 |
|---|---|---|
| historical event | 历史事件 | 按剧本条件触发的特定事件 |
| random event | 随机事件 | 按概率和状态条件触发的事件 |
| system event | 系统事件 | 与回合、死亡、继承、状态修正相关的系统性事件 |

## 六、架构术语

| 中文术语 | 英文术语 | 说明 |
|---|---|---|
| 分层架构 | Layered Architecture | 按职责拆分 UI、服务、内核、数据和存储 |
| 模拟内核 | Simulation Core | 负责状态演算的核心模块 |
| 规则数据层 | Rule Data Layer | 管理公式、技能、事件和剧本配置 |
| 数据驱动 | Data-driven Design | 通过配置数据控制系统行为 |
| 事件驱动 | Event-driven Design | 通过事件触发和效果执行推动状态变化 |
| 模块化 | Modularity | 将功能划分为职责清晰的模块 |
| 可测试性 | Testability | 系统核心功能能被自动化测试验证 |
| 可复现性 | Reproducibility | 同样输入和随机种子产生同样结果 |

## 七、命名一致性要求

1. 正式文档中统一使用 HistorySim Lite 作为案例名称；
2. 正式文档中统一使用 Region、Faction、Person、Army、Skill、Event、Command、GameState 等英文术语；
3. 命令英文标识必须使用大写形式；
4. 数据规模必须保持为 30 个 Region、4 个 Faction、50 个 Person、20 个 Skill、10 个 Event；
5. 核心算法组数量统一表述为 5 组；
6. 主要界面/面板统一表述为 4 组。
