# 文档模板与提交规范

## 一、最终提交目录建议

项目最终提交目录建议如下：

```text
HistorySim-Lite/
├── README.md
├── data/
│   ├── regions.*
│   ├── factions.*
│   ├── persons.*
│   ├── skills.*
│   └── events.*
├── src/
├── tests/
├── docs/
│   ├── SRS.md
│   ├── ARCHITECTURE.md
│   ├── ALGORITHMS.md
│   ├── TEST_REPORT.md
│   ├── USER_MANUAL.md
│   └── CONTRIBUTION.md
└── presentation/
    └── final-presentation.*
```

文件格式可根据技术栈调整，但文档名称和职责应保持一致。

## 二、README.md 模板

```text
# HistorySim Lite

## 1. 项目简介
说明系统目标、主要功能和课程背景。

## 2. 小组成员
列出成员、学号、角色和主要贡献。

## 3. 运行方式
说明安装依赖、启动系统、运行测试的方法。

## 4. 功能清单
列出已实现功能和未实现功能。

## 5. 数据规模
说明 30 个地区、4 个势力、50 个人物、20 个技能和 10 个事件。

## 6. 项目结构
说明主要目录和模块职责。

## 7. 测试方式
说明如何运行单元测试和集成测试。

## 8. 已知问题
列出限制和待改进内容。
```

## 九、命名规范

| 类型 | 规范 |
|---|---|
| 地区 ID | region_xxx |
| 势力 ID | faction_xxx |
| 人物 ID | person_xxx |
| 技能 ID | skill_xxx |
| 事件 ID | event_xxx |
| 军队 ID | army_xxx |
| 命令类型 | 使用大写英文标识 |

基础命令标识固定为：DEVELOP、RECRUIT、MOVE_ARMY、ATTACK、APPOINT。

## 十、提交要求

1. 每个阶段至少提交一次有效 Git commit；
2. commit message 应说明本次修改内容；
3. 不得在最终提交中删除历史提交记录；
4. 文档应与系统实现一致；
5. 测试报告不得只写“通过”，必须包含测试对象、输入、预期和结果；
6. 答辩前应确保系统能在教师指定环境中运行。
